Runtime stores

Data stores and live assets

These are the places where the application writes data during the hiring flow.

Database tables

  • Users for authentication and roles.
  • Candidate profiles and recruiter profiles.
  • Job postings and job applications.
  • Interview sessions and scoring data.
  • Saved jobs and analytics snapshots.

Upload locations

  • Resumes are written to uploads/resumes.
  • Interview recordings are written to uploads/interviews/recordings.
  • Interview snapshots are written to uploads/interviews/snapshots.

Current implementation

What is done right now

These items are already present in the current codebase and live app.

Candidate
  • Profile creation and updates.
  • Resume upload and ATS scanning.
  • Job browsing, saving, applying, and workflow tracking.
  • Interview flow with camera, transcript typing, and report output.
Recruiter
  • Job creation and editing.
  • Aptitude, technical, and coding rounds can be required or optional.
  • Interview scheduling and candidate review.
  • Analytics and recruiter access management.
AI stack
  • Gemini generates aptitude MCQs, technical MCQs, coding prompts, and interview questions.
  • ElevenLabs speaks the interview prompt aloud.
  • Interview report analysis is produced at the end of the workflow.

Current gaps

What is still pending or partially implemented

These are the outstanding items visible in the current build.

Partial
  • OAuth login exists on the backend, but the login screens do not expose Google/GitHub/LinkedIn buttons yet.
  • The "Forgot Password" UI is present, but a real reset flow is not implemented.
  • Candidate and recruiter support actions still show a coming-soon placeholder.
Partial
  • Recruiter AI optimization currently shows suggestion text, not a one-click AI rewrite workflow.
  • The proctoring layer is browser-based, so it is not yet a fully locked kiosk-style exam shell.
  • There is no built-in export button for the final interview report in the current UI.
Pending
  • Email or SMS notification workflows are not shown in the current code.
  • Calendar integrations are not visible yet.
  • More advanced support tooling and analytics export would still improve the product.
